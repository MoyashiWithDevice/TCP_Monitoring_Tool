# eBPF + Go による TCP 再送・原因分析可視化ツール 詳細設計仕様

## 目的

Linux カーネル内部で発生している TCP 再送イベントを eBPF (kprobe) により捕捉し、  
Go プログラムで受信・補完・DB保存することで、

> 「どのプロセスのどの通信が、なぜ不安定なのか」

を後から自由に分析できる観測基盤を構築する。

本ツールは単なる再送カウンタではなく、**原因分析可能な TCP 品質観測ツール**である。

---

## 全体アーキテクチャ

| レイヤ | 技術 | 役割 |
|---|---|---|
| カーネル | eBPF (C) + kprobe | TCP 再送イベントの捕捉 |
| ユーザーランド | Go | eBPFイベント受信・補完 |
| 永続化 | DB | 生イベントの保存 |
| 分析 | SQL / 可視化 | プロセス単位の再送・原因分析 |

---

## フック方式

**kprobe 型**を採用する。

理由：

- `sock` 構造体へ直接アクセス可能
- 再送の理由まで判別可能
- TCPスタック内部の情報を完全に取得可能

---

## フック対象カーネル関数

### 1. :contentReference[oaicite:0]{index=0}
- すべての再送が最終的に通る
- 「再送が発生した事実」を取得

### 2. :contentReference[oaicite:1]{index=1}
- Fast Retransmit の検出
- `retransmit_type = FAST`

### 3. :contentReference[oaicite:2]{index=2}
- Loss Probe の検出
- `retransmit_type = LOSS_PROBE`

### 4. RTO 判定
- `tcp_retransmit_skb` 内部状態から判定
- `retransmit_type = RTO`

---

## eBPF から送信するイベントデータ

| 項目 | 内容 |
|---|---|
| timestamp | 再送発生時刻 |
| pid | プロセスID |
| comm | プロセス名 |
| src_ip | 送信元IP |
| src_port | 送信元ポート |
| dst_ip | 宛先IP |
| dst_port | 宛先ポート |
| tcp_state | 再送発生時のTCP状態 |
| retransmit_type | FAST / RTO / LOSS_PROBE |

eBPF は**加工・集計を一切行わず、生イベントを送信するのみ**。

---

## Go 側で補完する情報

eBPF では取得困難な以下を Go 側で補完：

| 項目 | 取得方法 |
|---|---|
| process_start_time | `/proc/<pid>/stat` から取得（キャッシュ） |

これにより `(pid, process_start_time)` で一意なプロセス識別が可能。

## DB 設計

### テーブル定義例

```sql
CREATE TABLE tcp_retrans_events (
    id                  BIGSERIAL PRIMARY KEY,
    ts                  TIMESTAMPTZ NOT NULL,

    process_name        TEXT NOT NULL,
    pid                 INTEGER NOT NULL,
    process_start_time  BIGINT NOT NULL,

    src_ip              INET NOT NULL,
    src_port            INTEGER NOT NULL,
    dst_ip              INET NOT NULL,
    dst_port            INTEGER NOT NULL,

    tcp_state           TEXT,
    retransmit_type     TEXT
);
```

## インデックス
```SQL
CREATE INDEX idx_ts ON tcp_retrans_events(ts);
CREATE INDEX idx_process ON tcp_retrans_events(process_name);
CREATE INDEX idx_dst ON tcp_retrans_events(dst_ip, dst_port);
```
---
## 設計方針（重要）
- 1再送イベント = 1レコード保存
- Go 側で時間窓集計は行わない
- 分析・集計はすべて DB クエリで実施
- 主キーは意味を持たない連番ID
- 検索性能はインデックスで担保

---

## 可能となる分析例
- プロセス単位の総再送数
- 宛先IP/ポートごとの再送傾向
- 時間帯別の再送増減
- TCP状態別の再送分析
- 再送原因（FAST / RTO / LOSS_PROBE）分析
- プロセス生存期間全体での品質評価

---
## ツールの最終的な価値

本ツールにより、

>「再送が多い」ではなく
>「なぜその再送が起きているか」

をプロセス単位で説明できるようになる。
